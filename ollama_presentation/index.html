Ollama

A framework with an application as its interface — Ollama lets you download & run open-source AI models locally, protecting your data because it never leaves your machine. No API key. No expensive hardware. One command.

Presentation By: Kerven, Maia, & Skyla

Section 01 / Introduction

What is Ollama?

Before Ollama, open-source models were free to download but difficult to use, while proprietary models were easier to access through APIs — at the cost of your data. Ollama bridges that gap: run new open-source models in a single command.

Access Simplified

  • Download & run open-source AIs without an API key.
  • No expensive hardware needed for larger models — use Ollama Cloud.
  • Standardizes how models are installed, run, and managed.

Affordability & Privacy

  • Models run privately — data never leaves your computer.
  • Cloud access to larger models keeps data within Ollama's servers.
  • Contrast: governments (e.g. China, USA) can request your data from centralized AI providers.

Pros

Easy to Use Standardized Saves Money Keeps Data Private Build Apps from Local Machine Open Source Only
Section 02 / Use Cases

Open Source Usage

What You Can Do

  • Download & run open-source models entirely locally.
  • Swap models quickly to experiment with different capabilities.
  • Build apps & features powered by models on your own machine.
  • Work offline — local models need no internet connection.

What You Can't Do

  • Run or download proprietary / closed-source models through Ollama.
  • No hosted API dependence — you supply the hardware (or Ollama Cloud).
Section 03 / Downloading Ollama

One Command

Quick and straightforward — open your local terminal and paste the run command:

PS>irm https://ollama.com/install.ps1 | iex

Ollama itself requires very little to download — the total install size depends on the demands of whatever models you install onto it.

Section 04 / Money & Hardware Needs

Hardware

The Rules

  • 8–16GB RAM recommended for small or cloud-based models.
  • Runs on CPU from RAM, GPU (if available), or a mix of both — GPU is faster.
  • VRAM isn't required, but it dramatically speeds up responses.
  • Newer Apple Macs automatically split the workload between CPU & GPU.

Three Scenarios

  • Model fits in VRAM → GPU does all the work; best speed.
  • Model partly fits → some layers on GPU, rest on CPU/RAM; speed drops sharply, often to a fraction of full-GPU speed.
  • No GPU → everything runs from RAM on the CPU — slow, but fine for small models.
Community shorthand: a Q4-quantized model takes ~0.6GB of RAM or VRAM per billion parameters — leave a couple of GB extra for overhead to make sure the model functions. For systems with 4–6GB of VRAM, Phi-3 or Mistral are recommended; Qwen-mini is a good option to run locally too.

Section 07 / Interaction Paradigm

Prompt → Response

The basic unit of interaction is a text prompt. You provide a question, instructions, or content — the model generates a response. Ollama runs the model you choose.

What Do You Control?

  • The model, its instructions, and the context it receives.
  • Settings that influence responses.
  • Basic tasks: summarize a document, translate text, write code, brainstorm, adopt a tone.
  • Some models accept images — ask questions about visual content.
  • Where it runs: locally (your hardware, specs matter) or cloud (remote server).

Where Is Human Agency?

  • You define the task — ask what you need done.
  • You provide background — relevant information for better execution.
  • The model generates the response, but you decide what's useful and how to use it.

What It Makes Easy

  • Natural-language requests: summarize, translate, brainstorm, explain, generate code.
  • Quick change of the model being used — experiment locally.
  • Connect generated text to a project.
  • More privacy & control over your own data.
  • No Wi-Fi needed to run local models.
  • Cloud access for models too demanding for your computer.

What It Makes Hard

  • Models can misunderstand instructions, invent information, or give inconsistent answers.
  • Context window limits how much it can consider at once — fluent ≠ accurate.
  • Cloud use doesn't make answers accurate or give current information.
  • Local: memory, processing power & storage limit which models you can run and how fast.
  • Cloud: dependent on internet, service availability & usage limits — and less privacy.
Section 08 / Limits, Risks & Data

Where Does Your Data Go?

Prompts are retained transiently — only while relevant, then deleted shortly after (~5 minute retention). Prompts are never used for training.

Account Info

Login, name, date joined, etc. — retained.

Billing Records

Kept as required by tax & accounting law.

Support Comms

Crash reports and support correspondence.

Metadata & Analytics

How the service is used (e.g. model downloaded) — recorded temporarily, then deleted or de-identified.

Storage: data is stored on servers in the USA on NVIDIA GPUs. You can force Ollama to clear the model from VRAM before the retention window by typing --keep-alive 0 in the terminal.

Section 10 / Connection to Final Project

Where It Fits

Use
How we could use it
  • Run a local model as the brain of an interactive artwork — fully offline, fully private.
  • Generate live text for an installation without API costs per visitor.
Extend
What we'd need to extend
  • A custom interface beyond the terminal (web UI, physical input).
  • Tuned instructions/system prompt & model choice for the project's tone.
Risk
What could go wrong
  • Hallucinated or incoherent output in front of an audience.
  • Hardware bottleneck — slow responses on the exhibition machine.
  • Context-window limits forgetting earlier interaction.
